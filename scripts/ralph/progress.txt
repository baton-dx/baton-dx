## Codebase Patterns
- ClonedSource interface in git-clone.ts is the canonical return type for all git clone operations; any new fields must also be added to mock objects in github-resolver.test.ts and edge-cases.test.ts
- resolveGitHubSource returns its own ResolvedGitHubSource interface (subset of ClonedSource) — test assertions should not expect fields that aren't in the resolver's return type
- simpleGit mocking pattern: `vi.mock("simple-git")` at module level, then `vi.mocked(simpleGitModule.simpleGit).mockReturnValue({...})` in beforeEach
- Must run `bun run build` before `bun run typecheck` since CLI resolves @baton-dx/core from dist/
- Biome enforces parameter-per-line formatting for long function signatures
- Tests are co-located: `foo.test.ts` next to `foo.ts`
- For mocking a single export from a module, use `vi.mock("path", async (importOriginal) => ({ ...(await importOriginal()), fn: vi.fn() }))` to keep other exports real
- To mock `stat` from `node:fs/promises` while keeping other exports (mkdir, rm) real, use the partial mock pattern with `importOriginal`
- `isCacheStale` is a private function in git-clone.ts — test it indirectly through `cloneGitSource()` with `maxCacheAgeMs` set
- Cache staleness logic: `maxCacheAgeMs: 0` forces immediate fetch; `undefined` preserves existing best-effort pull behavior
- `FileNotFoundError` (from errors.ts) is the canonical error when `loadProfileManifest` can't find a file — check with `instanceof FileNotFoundError`
- `resolveChainRecursive` now re-throws all non-circular, non-max-depth errors with enhanced context message (US-003 completed)
- `GlobalConfig` type is NOT exported from `@baton-dx/core` index — use `loadGlobalConfig()` return type via inference, not explicit `type GlobalConfig` import
- Biome enforces alphabetical import sorting — `loadGlobalConfig` goes between `isLockedProfile` and `loadProfileManifest`
- To convert a single-file command to a directory with subcommands: rename `config.ts` → `config/index.ts`, update import path in CLI entry to `./commands/config/index.js`
- citty supports `subCommands` + `run()` on the same command: `run()` fires when no subcommand matches (default behavior)
- `loadProfileManifestSafe` in load-profile-safe.ts is the gatekeeper for profile discovery — if it silently swallows errors, profiles become invisible in `baton init` and `baton manage`
- To mock `readFile` from `node:fs/promises` while keeping dynamic import of the module under test, use `vi.mock()` before `await import()` pattern
