## Codebase Patterns
- Schema fields use private `const xxxSchema` (no export) — only `ProfileManifest` via `z.infer` is exported publicly
- Union schemas (`z.union([z.array(z.string()), z.record(...)])`) are the standard pattern for universal vs tool-specific targeting (used by rules, agents)
- Zod's `.object()` strips unknown keys by default — existing tests may pass with invalid data in undeclared fields
- Tests are co-located: `foo.test.ts` next to `foo.ts`, using `vitest` with `describe/it/expect`
- Must run `bun run build` before `bun run typecheck` since CLI resolves `@baton-dx/core` from `dist/`
- Merge functions follow identical structure: `mergeX()` wraps `mergeXWithWarnings()`, uses Map for dedup by composite key (`scope:name`), last-wins semantics
- Export blocks in `core/src/index.ts` use 2-space indent, group functions + types together, comment header per block
- Biome enforces 2-space indent — files written with tabs will fail lint
- Biome sorts imports: `type` imports must come before value imports within an import block
- The sync pipeline pattern is: Merge → Accumulate (into `contentAccumulator`) → Flush. New content types just need an accumulation loop and inclusion in the type union
- `AgentFile.frontmatter` is REQUIRED (unlike `RuleFile.frontmatter` which is optional). Always provide a fallback: `{ name: agentEntry.name }`
- The content flush at the end of sync handles any type in the accumulator generically — no flush changes needed when adding new content types
