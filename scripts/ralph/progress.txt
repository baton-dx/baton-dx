## Codebase Patterns
- Detection types live in `packages/agent-paths/src/types.ts` and are re-exported from `index.ts`
- All agent-paths types use `readonly` modifier on interface properties
- Barrel exports in `index.ts` use `export type {}` syntax for type-only exports
- `IdePlatformEntry` in `packages/core/src/ide/platform-registry.ts` imports types from `@baton-dx/agent-paths` using `import type`
- When adding types to agent-paths that core needs, build must run before typecheck (project references resolve against `.d.ts` files)
- Detection mechanism functions live in `packages/core/src/detection/mechanisms.ts`
- Mock `node:child_process` with `vi.mock("node:child_process", () => ({ execFile: vi.fn() }))` — mock must be before the import
- For `execFile` mocks, the callback is always the 4th arg: `(cmd, args, opts, cb)` — use `mockImplementationOnce` for sequential calls
- Use `Object.defineProperty(process, "platform", { value: "win32" })` to mock platform in tests (restore in afterEach)
- Mock `node:fs/promises` with `vi.mock("node:fs/promises", () => ({ access: vi.fn(), constants: { R_OK: 4 }, readdir: vi.fn() }))` — must include `constants` and `readdir` in the mock factory
- Mock `node:os` with `vi.mock("node:os", () => ({ homedir: vi.fn(() => "/home/testuser") }))` for tilde expansion testing
- For `fs.access` mocks: `mockResolvedValueOnce(undefined)` for success, `mockRejectedValueOnce(new Error("ENOENT"))` for missing
- Biome flags `continue` in catch blocks as `noUnnecessaryContinue` — use empty catch with comment instead
- For `readdir` mocks: `mockResolvedValueOnce(["entry-1.0.0", "other-2.0.0"])` returns an array of directory entry names
- `EDITOR_EXTENSION_DIRS` maps editor names to `~/.<editor>/extensions/` — used by `checkVscodeExtension`
- Extension directory entries follow the pattern `<extensionId>-<version>` — match by case-insensitive prefix
- JetBrains config base is platform-specific: macOS `~/Library/Application Support/JetBrains/`, Linux `~/.config/JetBrains/`, Windows `%APPDATA%/JetBrains/`
- JetBrains plugin directories are at `<config-base>/<IDE-version>/plugins/<plugin-id>/` — scan across all IDE version dirs
- For `readdir` chains (list dirs then list subdirs), use sequential `mockResolvedValueOnce` calls — they are consumed in order
- To mock `process.env.APPDATA` in tests: save original, set value, restore in cleanup (no `Object.defineProperty` needed for env vars)
- ESM modules don't allow `vi.spyOn` to intercept intra-module function calls — spy on an exported dispatch object (`checkHandlers`) instead
- `checkHandlers` in `mechanisms.ts` maps check types to their handler functions — `runCheck` dispatches through it so tests can `vi.spyOn(mechanisms.checkHandlers, "binary")`
- For `evaluateDetection` tests, spy on `mechanisms.checkHandlers` properties, NOT on `mechanisms.checkBinary` etc.
- IDE platform entries use different detection directories than agent entries for the same tool (e.g., Windsurf IDE uses `~/.windsurf/`, agent uses `~/.codeium/windsurf/`)
- IDE detection uses `extensions` as marker directory for VS Code-family IDEs (vscode, cursor, windsurf) to confirm actual IDE usage
- `AgentPathConfig` no longer has `detection: string[]` — all agents use `detectionConfig` exclusively
- `isAgentInstalled()` in `agent-detection.ts` only uses `evaluateDetection(detectionConfig)` — no legacy fallback
- `IdePlatformEntry` no longer has `detection: string[]` — `detectionConfig` is now required (non-optional)
- `isIdeInstalled()` in `ide/detection.ts` only uses `evaluateDetection(detectionConfig)` — no legacy fallback, mirrors agent-detection.ts pattern
